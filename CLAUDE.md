# CLAUDE.md

## Project

`alexa-memory-mcp` ("Memory Steward for Alexa+", tagline "It manages your memory. You own
it."; renamed from "Portable Memory" on Oct 20, repo and Python module names unchanged) is a self-hosted MCP server that gives
Alexa+ a long-term memory the user owns. The memory is a plain Markdown file (local disk
or Google Drive) that the user can read and edit by hand; assistants are clients of that
file, not its owner. Because voice is error-prone, writes are never silent:
`propose_memory` / `supersede_memory` stage a fact and return a read-back sentence, and
only `confirm_memory` saves it. Temporary facts carry review dates (`list_due_reviews`,
`resolve_review`). `recall` is fast keyword search over an in-memory cache; no LLM runs
in the server's request path (Alexa+ does NLU and phrasing). Solo entry for the
Alexa+ track of the "Build, Ship, Shape: Amazon Developer Hackathon" (deadline
Oct 23, 2026, 12:00 PM PT). See README.md for tools, config and layout.

## Alexa+ constraints and plan

- Participants have **no access** to the Alexa AI CLI, MCP Toolkit or devices
  (partner-gated). The track allows a simulated Alexa+ experience via a web app, so the
  judged demo is a **web simulator that is a real MCP client** of this server.
- Alexa+ requirements the server must meet:
  * Streamable HTTP, MCP spec 2025-11-25+.
  * Round-trip tool latency **< 500 ms** (proof: `scripts/bench.py`, `tests/test_latency.py`,
    `proof/latency-local.txt`). Keep storage and LLM calls out of the request path:
    reads come from the in-memory cache (`memory/cache.py`), Drive writes are write-behind.
  * Auth: OAuth 2.1 authorization code + PKCE (S256); unauthenticated requests get
    **401 without a `WWW-Authenticate` header**; Protected Resource Metadata per
    RFC 9728; AS metadata at `/.well-known/oauth-authorization-server`. No DCR, CIMD,
    OIDC or step-up: one pre-registered client. Every item is mapped to code and tests
    in `docs/ALEXA-READINESS.md`; keep that table true when auth changes.
  * Alexa+ does NLU and response generation itself; the server returns standard MCP
    results (no LLM in the server).
- Simulator (`simulator/`, port 8001): a real MCP client (official Python client, a
  short-lived connection per turn). The page is plain HTML/CSS/JS (`simulator/static/`, no
  build step, must work in Chrome). Brain: `SIM_BRAIN=bedrock` (Converse tool loop) or
  `scripted` (deterministic, offline). `ScriptedBrain` must keep handling exactly the
  golden conversations in `docs/demo-script.md`; `tests/test_simulator.py` checks them. If
  you change a golden line, change all three together.
- No logos or trademarks on the page; call it "Simulated Alexa+".
- Rules for using the memory tools live in ONE place: the Agent Skill
  `skills/memory-steward/` (SKILL.md short, details in references/). The simulator's
  hardcoded prompt is persona only; the server's `instructions` are the minimal
  model-agnostic contract. Change behaviour rules in the skill, then re-run
  `scripts/eval_bedrock.py --conversations 1,2,3,4,5,6`.
- Listing: `addon-package/addon.json` is generated by `scripts/make_addon.py` (documented
  fields only; don't add guessed fields, list unknowns in docs/ALEXA-READINESS.md). Assets
  are original (no Amazon/Alexa marks), exported by `scripts/render_assets.sh`.
- Privacy/terms: `docs/privacy.md` and `docs/terms.md` are served at /privacy and /terms.
  Keep them true when data flows change (new storage, new third party, token lifetimes).
- Auth design (`auth/`): custom, not the MCP SDK's built-in auth, because the SDK's
  `RequireAuthMiddleware` always sends `WWW-Authenticate` on 401, its handlers treat
  `resource` as optional and its metadata assumes dynamic registration; adapting it meant
  overriding most of it. `auth/oauth.py` is a minimal single-owner authorization server
  (owner passphrase as scrypt hash, rate-limited sign-in page) plus the /mcp check;
  `auth/tokens.py` issues opaque tokens stored only as SHA-256 hashes in a gitignored
  0600 file (`.oauth/tokens.json`), so they survive restarts; refresh tokens rotate and
  reuse revokes the family. Scopes reach tools through a contextvar
  (`require_scope`). Standard library + Starlette only; don't add an OAuth/JWT library
  without a reason. `MCP_BEARER_TOKEN` is a localhost-only dev token (refused publicly).
- The simulator links exactly like Alexa (`simulator/linking.py`): it is the registered
  client, tokens stay server-side in the simulator, never in the browser.

## Working rules

- **Never use real personal data.** Demo data is the fictional persona "Sam" in
  `demo_data/seed.py`. Never point the demo at real memory.
- **Never commit secrets**: `.env`, `service-account*.json`, tokens. Check `.gitignore`
  before committing; `.env.example` holds placeholders only.
- **All tests must pass before every commit.**
- Whenever a tool, SDK or doc causes friction, **add a row to `FRICTION_LOG.md`**
  (it earns a judging bonus).
- Keep commits small, with clear messages.

## Commands

```bash
# setup (Python 3.10+)
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python demo_data/seed.py     # reset demo_data/memories.md to the "Sam" persona

# run server (http://127.0.0.1:8000/mcp; config via env, see .env.example)
.venv/bin/python server.py

# run tests (unit + end-to-end Streamable HTTP test)
.venv/bin/python -m pytest -q

# owner passphrase hash for OWNER_PASSPHRASE_HASH (asks without echo)
.venv/bin/python -m auth.passphrase

# OAuth access token for dev tools (runs the real flow; needs OAUTH_CLIENT_ID/SECRET, OWNER_PASSPHRASE or prompt)
TOKEN=$(.venv/bin/python scripts/oauth_token.py http://127.0.0.1:8000/mcp --redirect-uri <registered uri>)

# latency benchmark against a running server (writes benchmark records: demo data only)
.venv/bin/python scripts/bench.py http://127.0.0.1:8000/mcp --token "$TOKEN"

# demo: memory server :8000 + Simulated Alexa+ :8001 on a temp copy of the demo data;
# click "Link account" and use the owner passphrase the script prints
SIM_BRAIN=scripted scripts/run_demo.sh                       # offline
BEDROCK_MODEL_ID=... AWS_REGION=... scripts/run_demo.sh      # Bedrock brain

# real Google Drive checks (manual; resets the demo file to the seed at the end)
DRIVE_FOLDER_ID=... GOOGLE_APPLICATION_CREDENTIALS=... .venv/bin/python scripts/drive_smoke.py

# Bedrock evaluation (manual, costs money): 5 golden conversations x3 -> proof/bedrock-eval.txt
AWS_REGION=us-east-1 .venv/bin/python scripts/eval_bedrock.py http://127.0.0.1:8000/mcp --token "$TOKEN" us.amazon.nova-pro-v1:0

# Bedrock smoke check (manual, costs money): conversations 1-2 -> proof/bedrock-smoke.txt
.venv/bin/python scripts/bedrock_smoke.py http://127.0.0.1:8000/mcp --token "$TOKEN"
```

Never read, print or store AWS credentials; rely on the default credential chain.
Never log or commit OAuth tokens, client secrets or the owner passphrase; proofs show `***`.
